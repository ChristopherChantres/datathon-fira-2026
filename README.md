# AgroCebada FIRA 2026 · Web

Interactive website for our entry to the **Reto AgroCebada FIRA 2026**. It explains how
our barley-yield model works and lets the jury run it in the browser on the 59 parcels
we had to predict. The page is in Spanish (Mexico); code and docs are in English.

The browser runs the same formula as the validated Python model and is tested to match
its predictions to 1e-9 for every parcel.

## Structure

```
├── CLAUDE.md          project rules and the data contract
├── data/              generated by model/export_web_data.py (read-only)
├── docs/              model figures (model.md) and visual style (palette.md)
├── model/             the validated Python model the data comes from (read-only)
├── web/               the site: Vite + React 18 + TypeScript
│   ├── scripts/sync-data.mjs   copies ../data into web/public/data
│   └── src/
│       ├── data/      types mirroring the data contract, loaders, React hooks
│       ├── model/     predict() and its tests against /data
│       ├── components/ map, formula, nav, dev-only debug panel
│       ├── content/   section ids and Spanish copy
│       ├── lib/       GSAP setup, formatting
│       └── styles/    design tokens and base styles
├── Dockerfile         build (tests + bundle) → nginx on port 8080
├── nginx.conf
└── DEPLOY.md          exact deploy commands
```

## Run

Requires Node ≥ 20.19.

```bash
cd web
npm ci
npm run dev        # http://localhost:5173
```

`dev`, `build` and `test` first run `sync-data`, which copies `../data` into
`web/public/data` (gitignored). Never edit the copies; the originals in `/data` are the
source of truth.

In development, a **Debug** button (bottom right) compares `predict()` with the stored
Python values for any predict parcel. It is not included in production builds.

## Test and check

```bash
cd web
npm test           # Vitest: browser model == Python model, data integrity
npm run typecheck  # tsc --noEmit (strict)
npm run build      # typecheck + production bundle in web/dist
npm run preview    # serve the production bundle locally
```

## Deploy

See [DEPLOY.md](DEPLOY.md). In short, from the repo root:

```bash
gcloud run deploy agrocebada-web --source . --region us-central1 --allow-unauthenticated --port 8080
```

## Updating the model data

Only when the model changes, and only Christopher:

```bash
python model/export_web_data.py --dataset path/to/DATASET_RETO_AGRO_2026
```

Then `npm test` in `web/` confirms the site still reproduces the new predictions.
